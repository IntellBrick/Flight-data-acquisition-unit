# 空速计测试结果

日期：2026-11-15
被测设备：CUAV SKYE2 空速计（`net.cuav.skye-2`，软件 1.3，硬件 0.1，vcs `bbded377`）
测试环境：Makerbase CANable 2.0（slcan，COM10，1 Mbit/s 经典 CAN）
测试工具：`tools/skye2_test.py`（UAVCAN v0 动态节点 ID 分配器 + 空气数据解码）

## 1. 结论

**SKYE2 空速计通信与测量功能正常，可直接进入 STM32 侧驱动开发。** 已验证：动态节点 ID 分配、设备识别、NodeStatus 心跳、RawAirData 数据流（约 50 Hz）、吹气动态响应（压差 -9 Pa → +452 Pa）、板载湿度计。累计 4243 条多帧传输 CRC 校验失败 0 次。

| 设备识别（GetNodeInfo） | ✅ `net.cuav.skye-2` sw 1.3 hw 0.1 |

## 2. CAN 总线与协议参数

### 2.1 物理层 / 总线

| 参数 | 值 | 备注 |
|---|---|---|
| 位速率 | **1 Mbit/s** | 实测唯一可用值（设备默认）；其他速率未测试 |
| 帧格式 | 经典 CAN 2.0B，29 位扩展帧 | 全部报文均为扩展帧 |
| 电平/接线 | CAN_H ↔ CAN_H，CAN_L ↔ CAN_L，双绞 | 实测约 20 cm 短线无终端电阻可通信；正式布线须两端各 120 Ω |
| 共地 | 传感器供电电源 GND 与主控 GND 必须连通 | — |

### 2.2 DroneCAN（UAVCAN v0）CAN ID 布局

| 帧类型 | 位域布局（bit 28 → bit 0） |
|---|---|
| 消息帧 | `优先级[28:24] | 数据类型ID[23:8] | 0[7] | 源节点ID[6:0]` |
| 匿名帧（分配请求） | `优先级[28:24] | 随机判别码[23:10] | dtid低2位[9:8] | 0[7] | 0000000` |
| 服务帧 | `优先级[28:24] | 服务类型ID[23:16] | 请求/响应[15] | 目标节点[14:8] | 1[7] | 源节点ID[6:0]` |

实测设备广播优先级 = 24（低）；本方分配器使用 30 均被正常接受。

### 2.3 传输层（多帧传输）

| 项目 | 规则 |
|---|---|
| 尾字节 | `S<<7 \| E<<6 \| T<<5 \| transfer_id[4:0]`；S=首帧，E=末帧，T=toggle 位（首帧后逐帧取反），transfer_id 5 位循环 |
| 单帧传输 | 负载 ≤ 7 字节，S=E=1 |
| 多帧传输 | 首帧以 2 字节小端传输 CRC 开头；每帧负载 7 字节（末帧余量） |
| 传输 CRC | CRC-16-CCITT-FALSE，覆盖 **数据类型签名（8 字节小端）+ 负载** |
| 重组键 | (源节点, dtid, 服务标志, 请求标志, transfer_id) |

| 分配消息优先级 | 30（实测可用） | — |
| 分配超时 | 500 ms 无后续请求则复位阶段状态 | 规范 FOLLOWUP_TIMEOUT |

### 3.2 动态节点 ID 分配流程（必须实现）

SKYE2 上电后 `CAN_NODE_ID=0`，以匿名节点周期（约 0.6–1 s）发出分配请求，**未获授权前不发布任何数据**。分配交互按规范分 3 阶段交付 16 字节 unique ID（6+6+4）：

```
设备 → 匿名请求 stage1（first_part=1，6 字节 uid）
主控 → 单帧回发 echo（node_id=0 + 已收 6 字节）        ← follow-up
设备 → 匿名请求 stage2（6 字节，累计 12）
主控 → 多帧回发 echo（node_id=0 + 12 字节，含传输 CRC） ← follow-up
设备 → 匿名请求 stage3（4 字节，累计 16）
主控 → 多帧发送 grant（node_id<<1 | 完整 16 字节 uid）   ← 授权
设备 → 立即以授予的节点 ID 发布 NodeStatus（不重启）
```

- unique ID（本台设备）：`51 00 35 00 12 50 47 51 53 31 31 20 00 00 00 00`（内含 ASCII "GPQS11"，疑为序列号）；
- **授权报文必须回显完整 16 字节**（设备 uid 以 `00 00 00 00` 结尾，最后 4 字节只能从 stage 3 获得——缺少第 3 阶段交换是常见实现错误）；
- 节点 ID **断电不保持**：主控每次上电都必须重新运行分配器；
- 推荐授予 ID：125（或按设备唯一 ID 固定映射，便于日志溯源）。

### 3.3 上电初始化时序（实测有效顺序）

| 步骤 | 动作 | 判据 / 超时 |
|---|---|---|
| 1 | FDCAN 初始化（1 Mbit/s，经典模式），本机以节点 100 上线 | — |
| 2 | 运行分配器状态机 | 收到 grant 被接受；设备 1–2 s 内开始发 NodeStatus |

### 4.1 消息台账（实测）

| 数据类型 | dtid | 消息率 | 帧数/条 | 负载长度 | 传输 CRC 签名（64 位） |
|---|---|---|---|---|---|
| uavcan.protocol.NodeStatus | 341 | 1.00 Hz | 1 | 7 字节 | 0x0F0868D0C1A7C6F1 |

### 4.2 RawAirData（dtid 1027）负载布局（17 字节，小端、字节对齐）

| 偏移 | 字段 | 类型 | 实测行为 |
|---|---|---|---|
| 0 | flags（bit0 加热可用 / bit1 加热中 / bit2 过流 / bit3 开路） | u8 | **恒为 0x00，未填充** |
| 1–4 | static_pressure | f32 (Pa) | **恒为 NaN，不发布** |
| 5–8 | differential_pressure | f32 (Pa) | ✅ 有效；实测 -9.9（静置）… +452.0（吹气峰值） |
| 9–10 | static_pressure_sensor_temperature | f16 (K) | 恒为 NaN |
| 11–12 | differential_pressure_sensor_temperature | f16 (K) | 恒为 NaN |
| 13–14 | static_air_temperature | f16 (K) | ✅ 有效；实测 319.75 K（46.6 °C，含自热） |
| 15–16 | pitot_temperature | f16 | ⚠️ 实测 39.6，**按 °C 语义处理**（见 6.1） |

## 5. 数据处理要求

| 项目 | 要求 |
|---|---|
| 空速换算 | IAS = sqrt(2 × dP / 1.225) m/s；dP < 0 时按 0 处理 |
| 零偏校准 | 静置零偏实测约 **-9 Pa**；建议主控上电初始化阶段（分配完成后）采集 2–3 s 均值作为零偏扣除 |
| NaN 判定 | f32：指数全 1 且尾数非零；f16：0x7E00/0x7C00 等。未填充字段一律按"无效"处理，不得参与运算 |
| 接收时间戳 | 在 FDCAN 接收中断入口取统一单调时钟，勿在解码任务中补打 |
| 离线判定 | 节点 3 s 无 NodeStatus 判离线，标记数据无效并保留最后值与时间 |
| 建议记录 | dP 原始值、IAS、零偏、static_air_temperature、湿度、NodeStatus、CRC 失败计数 |

## 6. 配置与硬件连接注意事项

### 6.1 固件字段单位疑似错置（重要）

- `RawAirData.pitot_temperature`：DSDL 定义为开尔文，实测值 39.59 按开尔文解释为 -233.6 °C（不可能），按**摄氏度**解释合理（与湿度计温度一致）；
- `Hygrometer.temperature`：DSDL 定义为摄氏度，实测值 312.75–313.00 按摄氏度解释不可能，按**开尔文**解释合理（39.6–39.9 °C）。

两字段单位互为镜像，判定为固件 bug（sw 1.3）。**STM32 采集代码按上述实测语义处理，勿按 DSDL 注释**；后续固件升级时需复测确认。

### 6.2 静压不可用

本设备不发布 static_pressure（恒 NaN）与 StaticPressure/StaticTemperature（dtid 1028/1029，从未出现）。气压高度需由 GPS 或独立气压计提供。

### 6.3 加热功能

- 加热器状态位（flags）恒为 0，无法经总线观测加热是否工作；
- 加热为 35 W 峰值功率，**必须由满足规格的独立电源供电，禁止从主控板或 CAN 适配器取电**；
- 加热验证方法：低温环境（<5 °C）下观察皮托管温度是否显著高于环境并稳定；或经参数协议（uavcan.protocol.param.GetSet）读取加热参数（本次未实施）。

### 6.4 其他

- 设备**未实现 GetDataTypeInfo 服务**（无响应），勿依赖；
- 节点 ID 断电不保持，主控每次上电必须重新分配；
- 供电与 CAN 接口线序以模块丝印为准；与适配器/主控连接器引脚顺序不同，按信号名接线；
- 正式布线：线型主干、双绞、仅两端 120 Ω 终端、可靠共地。
